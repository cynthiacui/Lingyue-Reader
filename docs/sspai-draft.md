# 写了一个不推荐、不订阅、不收社交的中文小说阅读器，给那些只想安静读完一本书的人

> 作者注：我是「灵阅书屋」的开发者。这篇是开发者自述，不是第三方评测，请按这个 frame 阅读。

![卷首图](../docs/screenshots/10-reader-paginated.png)

## 一、起因：我只是想读完一本几年前看过的网文

去年某个周末，我想重读一本十年前在起点追过的老网文。打开手头能找到的几个 App，依次碰到了下面这些：

- **微信读书**——搜不到，那本书从来没上过腾讯的书库。
- **番茄小说**——能搜到，但每翻三章弹一次「看 15 秒广告解锁下一章」。
- **起点读书**——能搜到，月票订阅 + 章节按千字计费，重温一本旧书要先充值。
- **Moon+ Reader**——能装，但要我自己去某个我说不出名字的地方找 EPUB，下下来还得手动改章节分隔符。
- **iBooks（现在叫 Books）**——根本不收这种书。

那天我意识到一件事：**对于「我已经知道自己想读什么、不需要算法推荐、也不打算和谁讨论」的成年读者，2025 年的中文阅读器市场是空白的。** 所有主流产品要么靠广告变现、要么靠社交粘性、要么靠订阅，没有一个愿意安静地把「读完一本书」当成唯一目标。

于是我用周末的时间写了一个，叫**灵阅书屋**。这篇讲它做了什么、没做什么、以及为什么。

## 二、它是什么

一句话定位：**一个纯本地、无广告、无账号、原生 SwiftUI 的 iOS 中文小说阅读器，书源由用户自己挂载**。

- iOS 17+，单窗口 App，包名 `com.lingyue.reader`
- 无第三方依赖（连 Swift Package Manager 都没用）
- 无内购、无订阅、无 IAP、无内置广告
- 无账号系统，也就没有云同步——所有数据都在你自己的设备上
- 内置一套小巧的「书源规则」引擎，可以让任意一个网页型小说站变成可搜索的书库；规则文件你可以自己写，也可以从别人那里导入一份 JSON

最后一条是关键，也是后面会展开讲的设计取舍。

## 三、三个最锋利的设计决定

我不打算罗列功能清单——README 里有。这一节只讲三个**我觉得和市面上其他阅读器拉开距离**的决定。

### 决定一：把"找书"这件事还给用户

![发现页](../docs/screenshots/05-discovery-search-results.png)

绝大多数中文小说 App 的「发现」或「书城」页是这样工作的：服务器维护一个书库，按算法/编辑推荐排序，你在他们划好的池子里挑。这套机制决定了——他们必然要做版权采买，必然要有广告或订阅来摊成本，也必然要追踪你读什么来优化推荐。

灵阅的「发现」页**默认是空的**。

你需要先去「书源」页加至少一个书源。来源有三种：

1. **手动添加**——填几个示例 URL（书源主页、一本书的目录页、一章正文、一次搜索的结果页），App 会自己抓页面、推断出选择器。这是少数派读者最容易低估的部分：你**不用懂任何选择器或正则**，也不用看任何文档。
2. **从 JSON 文件导入**——别人给你一份打包好的规则。
3. **从网址导入**——同上，但规则放在 raw URL 上，可以用 `lingyue://import?url=…` 深链一键唤起。

加完之后，「发现」页顶部的搜索框就会**并行**查询所有启用的书源，谁先返回谁先展示，同一本书被多个站点收录会自动合并成一行、用小标签列出来源。

这个设计有两层意味：

- **App 自己不持有任何书库**，也就没有版权问题，没有审核风险，也没有动力来推荐什么给你。
- **你看什么完全是你自己的选择**——灵阅既不知道，也无从知道。

### 决定二：阅读交互照搬 Apple Books，但比 Apple Books 多十几个旋钮

![阅读偏好](../docs/screenshots/11-reader-preferences.png)

Apple Books 的阅读交互有几个细节，业内做得好的不多：

- 轻点页面唤出工具栏时，**正文位置不动**——很多 App 这一下会重新分页，你刚读到的那一行会跳走。
- 状态栏和顶部/底部工具栏的显隐是**联动**的。
- 翻页动画里仿真翻页要做到不卡顿、不撕裂。

我把这些全部还原了，并且在仿真翻页上做了一版 `UIPageViewController` 的定制，避免了 SwiftUI 原生 `TabView` paging 在长文本时的几个 corner case。

但和 Apple Books 不同的是：

- **5 种页面底色**（纸张 / 米黄 / 护眼 / 雅蓝 / 夜读，夜读可跟随系统深色）
- **5 种字体**（苹方、宋体、楷体——内置开源 LXGW 文楷 Screen——黑体、圆体）
- **3 种翻页动画**（无 / 滑动 / 仿真翻页）
- **字号 / 行距 / 段距 / 简繁切换 / 自动滚读** 一处全调
- **章节列表带进度条**，长卷可以一眼看出"我快读完了"

这一切都在一个阅读页内的浮层里调，不需要进设置页。

### 决定三：主题系统不是配色，是氛围

![主题 - 樱粉](../docs/screenshots/15-theme-sakura.png) ![主题 - 水墨](../docs/screenshots/16-theme-ink.png) ![主题 - 星夜](../docs/screenshots/17-theme-starry.png)

5 套全局主题——纸张（默认）/ 樱粉 / 叶绿 / 水墨 / 星夜。它们**不只是改了几个颜色值**：

- 主题作用在所有顶层页面**以及内置浏览器**——浏览网页时网页背景透明，主题色透出来
- 「跟随系统深色模式」开关可以让 App 在系统切深色时自动换到星夜主题
- 主题资源是矢量 + 渐变 + 粒子的组合，不是几张大背景图

为什么花这么多力气做主题？因为**一个你愿意每天打开的阅读器，氛围比功能更重要**。这是一个我自己用下来才意识到的事。

## 四、那些"看似小但真香"的细节

罗列几个我自己最爱用的：

- **钱包式书架**——分类默认收成一叠书脊，轻点展开。我有 4 个分类、80 多本书，主屏不会糊成一片。
- **左/右滑书本**——左滑「下载 / 清理缓存」，右滑「删除」，仿邮件 App 的肌肉记忆。
- **下载管理器**——书架右上角的下载按钮调出一个弹层，集中看正在下载或已暂停的章节任务，不需要进每本书查。
- **内置浏览器一键导入**——浏览任何书源首页时，自动识别书籍页并弹出「导入到书架」按钮。
- **TXT/EPUB/HTML 本地导入**——TXT 会按「第 N 章 / 节 / 回 / 卷 / 页」自动拆章节，中文数字和阿拉伯数字都识别；EPUB 走 `<spine>`；HTML 去标签后按 TXT 同规则切。
- **阅读统计**——今日 / 连读天数 / 累计字数 / 时段分布 / 按书时长 / 日历热力图，全部本地计算，不上传任何服务器。读完一章可以生成一张分享卡片。

## 五、缺点 / 不适合谁

这一节我必须诚实，否则前面的话都不值得信。

- **没有云同步**——换设备进度、书架、书源不会自动迁移。可以用「我 → 数据 → 导出备份」整机导出导入，但那是手动的。
- **只有 iOS**。没有 Android、没有 Mac Catalyst、没有 iPad 独立适配（iPad 上能用，但布局是放大的 iPhone）。
- **不内置任何书源**——你必须自己加。这是设计取舍，不是漏洞，但对完全不愿动手的用户确实是门槛。
- **不支持漫画、有声书、PDF**。
- **没有任何社交功能**——不能加好友、不能看别人在读什么、不能写书评广播。如果你享受微信读书的"读书是一种连接"，灵阅不是为你设计的。
- **暂不支持竖排古籍**——虽然主题里有水墨，但排版还是横排。

如果你需要上面任何一项，**不要下载**，会失望。

## 六、横向对比

为了避免变成"自卖自夸"，我把我用过的几个主要竞品列在这里，包括它们做得比我好的地方。

| App | 它擅长的 | 它不擅长的 |
|---|---|---|
| **微信读书** | 出版书库巨大、社交活跃、Mac/Win/Web 全平台 | 老网文/小众网文几乎没有；推荐和广播打扰；账号绑定腾讯 |
| **番茄/七猫** | 免费、书库全 | 广告轰炸；算法推荐重；隐私 |
| **起点读书** | 正版网文最全、作者直发 | 订阅 + 千字付费；UI 偏旧；APP 内推广多 |
| **Moon+ Reader** (Android) | 可玩性极高、格式支持广 | iOS 不可用；要自己找文件；UI 是 2015 年风格 |
| **KyBook 3** | 老牌的「书源型」iOS 阅读器 | 长期未更新、UI 老旧、阅读体验不如 Apple Books |
| **Apple Books** | 系统级集成、阅读体验顶级 | 中文小说基本没有；本地导入后无在线搜索能力 |
| **灵阅** | 原生 SwiftUI、无广告无订阅、自带书源引擎、Apple Books 级阅读体验、五套主题 | iOS only、无云同步、不内置书源、无社交 |

简而言之：如果你之前在「KyBook + 自己导 EPUB」的方案下凑合多年、或者一直找不到一个**敢和 Apple Books 比阅读交互**的中文阅读器，灵阅可能就是你在找的。

## 七、关于书源：一个设计哲学的解释

写到这里必须单独讲一节，否则评论区一定会有人问。

灵阅的代码、App Store 二进制、官方仓库**都不包含任何在线书源 URL**。「书源」这套规则引擎是一个**通用的网页解析框架**，至于你拿它去解析什么网页，是你的选择，也只能是你的选择。

这有几个明确的好处：

1. **过审稳**——App 本身不分发版权内容，也不提供任何指向特定内容站点的链接。
2. **生命周期长**——任何在线书源都可能哪天失效，但只要 App 解析引擎在，社区可以自己维护新规则。
3. **责任清晰**——你自己挂的源、自己读的书，App 不知情。

这种"工具与内容分离"的思路，少数派读者应该不陌生——它和 RSS 阅读器、Newsboat、甚至 yt-dlp 是同一个哲学。**App 提供能力，用户决定用途**。
